# Job Queue and Worker (B3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A queued `process_book` job turns a stored upload into a parsed book with chapters, with
job and book status kept in PostgreSQL.

**Architecture:** The API side calls `enqueue_job()`, which puts the job UUID on the ARQ queue. The
worker task `process_book` reads the job and book from PostgreSQL, runs the parser from
`app.parsing` in a thread, and writes chapters and status back. Parser failures fail the job at
once; other exceptions are retried by ARQ up to 3 tries.

**Tech Stack:** Python 3.12, ARQ 0.26+, SQLAlchemy 2 async, pytest + anyio, PostgreSQL (pgvector).

**Spec:** `docs/superpowers/specs/2026-11-21-job-queue-design.md`; also
`docs/contracts/parse_book.md` section 5 and `docs/specification.md` sections 4.5, 5.4, Appendix C.

## Global Constraints

- Track B files only: `backend/app/worker/`, `backend/app/core/`, `backend/tests/` (not
  `tests/parsing/`), `docs/specification.md`, `README.md`. Never edit `app/parsing/*`.
- Worker code imports the parser only from `app.parsing` (`get_parse_book`, `ParseError`,
  `ContractViolation`, `validate_parsed_book`).
- `validate_parsed_book()` is called before anything is saved.
- Tests never need Redis or paid APIs. Database tests skip when `TEST_DATABASE_URL` is unset.
- `ruff check .` and `ruff format --check .` pass; line length 100; type hints everywhere.
- `MAX_TRIES = 3`.
- Run tests in Python 3.12 (the host has 3.11): see "Running tests" below.

## Running tests

```bash
docker run --rm -v "$PWD/backend:/app" -w /app --network bookcrunchai_default \
  -e BOOKCRUNCH_PARSER=fake \
  -e TEST_DATABASE_URL=postgresql+asyncpg://bookcrunch:bookcrunch@postgres:5432/bookcrunch_test \
  bookcrunch-backend-dev sh -c "ruff check . && ruff format --check . && pytest -q"
```

`bookcrunch-backend-dev` is a local throwaway image: `python:3.12-slim` with
`pip install -e ".[dev]"` dependencies (built once in Task 1, not committed).

## Review Focus

1. Title longer than 500 or author longer than 300 characters from the parser: the book is saved
   with the value cut to the column length, not failed with a database error. (Task 1)
2. The stored file is missing on disk: the job fails with `CORRUPT_FILE` (fake parser) or whatever
   the parser raises, not a retry loop. (Task 2, covered by the "other exception from the parser"
   test: nothing raised inside the parser call is ever retried.)
3. A job whose book failed earlier is processed again: old `error_code` on the book and job is
   cleared on success. (Task 1)
4. The same job delivered twice (ARQ re-delivery after `done`): second run changes nothing.
   (Task 1)
5. Writing the failure itself fails (database down on the last try): the exception propagates and
   is logged; nothing else can be done. Not tested; mention in the pull request.
