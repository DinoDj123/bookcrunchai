# Parser (Track A, Week 1: A2–A5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `parse_book(file_path) -> ParsedBook` for EPUB and text-based PDF that passes
`validate_parsed_book()` and gives the expected chapters on Pride and Prejudice, The Prince and
Meditations, ready for Daris to switch `BOOKCRUNCH_PARSER` to `real` at the end of Week 1.

**Architecture:** Format readers (`epub.py`, `pdf.py`) turn a file into an internal `RawDocument`
(clean blocks + TOC). `chapters.py` turns blocks into contract `Chapter`s. `parser.py` detects the
format by signature and assembles the `ParsedBook`. Details and reasons:
`docs/superpowers/specs/2026-11-23-parser-design.md` (read it first).

**Tech Stack:** Python 3.12, PyMuPDF (`pymupdf`), BeautifulSoup 4 + lxml, stdlib `zipfile`, pytest.

**Spec:** `docs/specification.md` FR-003, FR-004, FR-005; `docs/contracts/parse_book.md` v1.0;
`backend/app/parsing/contract.py` (code wins over docs).

## Global Constraints

- Track A files only: `backend/app/parsing/` **except** `contract.py`, `__init__.py`, `fake.py`;
  `backend/tests/parsing/` **except** `test_contract.py`; `backend/tests/fixtures/books/`;
  `docs/superpowers/{specs,plans}/*parser*`. One allowed edit in a Track B file: adding the parsing
  libraries to `dependencies` in `backend/pyproject.toml` (the file's own comment invites it; say so
  in the PR description).

  change in the PR description instead.
- Use `normalize_text()` for every paragraph and title and `count_words()` for every word count,
  both from `app.parsing.contract`.
- Raise only `ParseError` for expected failures; convert library exceptions only at the reader
  boundary; never `except Exception`.
- Parsing code: no database, no network, no file writes, no global mutable state, deterministic.
  Tests may write to `tmp_path`.
- No paid APIs anywhere in this plan.
- `ruff check .` and `ruff format --check .` pass (line length 100); type hints everywhere;
  `pytest tests/parsing/test_contract.py` keeps passing.
- Every test that produces a `ParsedBook` calls `validate_parsed_book()` on it.
- Commits: small and meaningful. Messages end with the attribution lines your environment requires.

## Review Focus

1. EPUB font obfuscation (`META-INF/encryption.xml` with the IDPF/Adobe font algorithms) is NOT
   reported as `ENCRYPTED_FILE`. (A2)
2. No Gutenberg licence text anywhere in the output, including chapter titles. (A2, A5)
3. A library exception other than the ones mapped to `CORRUPT_FILE` propagates (it is a bug), it is
   not silently turned into a `ParseError`. (A2, A3)
4. PDF: running header/footer lines and page numbers never appear in paragraphs; soft-hyphen words
   are joined (`errors`, not `er rors`); drop caps joined (`All states`, not `A ll states`). (A3)
5. Paragraph that continues across a PDF page keeps the page where it started; pages never
   decrease. (A3)
6. Kinds never break the order `front_matter* → chapter+ → back_matter*`. (A4)
7. Same file parsed twice gives equal `to_dict()`. (A5)
